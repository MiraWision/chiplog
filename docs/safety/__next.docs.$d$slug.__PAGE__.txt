3:T351d,<h1 id="redaction-and-limits"><a class="anchor" href="#redaction-and-limits" aria-label="Link to this section">Redaction and limits</a></h1><p>A wide event is a good trade with one sharp edge: it swaps &quot;lose one line&quot; for &quot;lose the whole
operation&quot;. If a record grows past what your backend accepts, the backend drops it — and the flow
you most wanted to read is exactly the pathological one that got dropped.</p>
<p>So everything entering an event is bounded, and everything is filtered.</p>

<div class="callout callout-fail"><p class="callout-label">Caution</p><p>Redaction is a hook, not a default. chiplog does not ship a built-in list of &quot;sensitive&quot; key names,
because a list that looks complete is worse than no list — the shape of sensitive data is specific
to your domain. Decide once, at instance creation, and it applies everywhere.</p>
</div><h2 id="limits"><a class="anchor" href="#limits" aria-label="Link to this section">Limits</a></h2><div class="table-scroll"><table><thead><tr><th>Option</th><th>Default</th><th>Effect</th></tr></thead><tbody><tr><td><code>maxStages</code></td><td>200</td><td>Keeps the first and last halves; the rest are counted in <code>droppedStages</code></td></tr><tr><td><code>keepFirstStages</code> / <code>keepLastStages</code></td><td>half of <code>maxStages</code></td><td>Tune the retention split</td></tr><tr><td><code>maxStringLength</code></td><td>2048</td><td>Truncates with a <code>…(+N)</code> marker</td></tr><tr><td><code>maxKeys</code></td><td>64</td><td>Object width, with a <code>&quot;…&quot;: &quot;(+N keys)&quot;</code> marker</td></tr><tr><td><code>maxArrayLength</code></td><td>64</td><td>Array length, with a <code>&quot;…(+N items)&quot;</code> entry</td></tr><tr><td><code>maxDepth</code></td><td>6</td><td>Deeper values become <code>&quot;[depth limit]&quot;</code></td></tr></tbody></table></div><p>The stage cap applies <strong>while accumulating</strong>, not at flush: a retry loop calling <code>stage()</code> a hundred
thousand times keeps memory flat and still produces a readable record.</p>

Values that would break or bloat serialisation are reduced to
labels:</p>
<div class="table-scroll"><table><thead><tr><th>Input</th><th>In the event</th></tr></thead><tbody><tr><td>circular reference</td><td><code>&quot;[circular]&quot;</code></td></tr><tr><td><code>Buffer</code> / typed array</td><td><code>&quot;[Uint8Array(1024 bytes)]&quot;</code></td></tr><tr><td><code>Error</code></td><td><code>{ &quot;name&quot;: …, &quot;message&quot;: … }</code></td></tr><tr><td><code>Date</code></td><td>ISO string</td></tr><tr><td><code>Map</code> / <code>Set</code></td><td>object / array</td></tr><tr><td><code>BigInt</code></td><td><code>&quot;10n&quot;</code></td></tr><tr><td><code>NaN</code>, <code>Infinity</code></td><td><code>&quot;NaN&quot;</code>, <code>&quot;Infinity&quot;</code></td></tr><tr><td>function, symbol</td><td>dropped</td></tr></tbody></table></div><p>Nothing here throws. A bad value in a log call must never become an incident of its own.</p>
